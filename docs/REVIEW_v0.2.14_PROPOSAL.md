**Review date:** 19 September 2026

**Reviewer's branch:** `arena/01a0b9f6-estate-tracking` (no code changed, no PR opened, `main` untouched)
**How this review was done:** gates re-run from a clean install; every document in the reading list read; the schema, migrations, stores, actions, API routes, service worker, manifest and all UI components read in full; the demo app exercised over HTTP as Alex; the calendar and checklist rendered to static markup with the real components and demo data; three targeted experiments run against the real code paths (results quoted below). No browser and no Android phone exist in this sandbox, so drag-and-drop, the on-phone share flow and visual appearance were reviewed by code-reading only, as every session before this one has also had to do.

## 1. Executive summary

The repository is in genuinely good health. From a clean install, all gates pass exactly as documented: 120 unit/integration tests, `tsc --noEmit`, Prettier, the production build (with the four known Turbopack tracing warnings), 0 production `npm audit` findings and the 4 documented moderate dev-only findings. The security posture held up under probing: every route and action verifies identity independently and fails closed, the production server really does send `private, no-store` on pages and APIs, uploads are name-sanitised against path traversal, and the backup format is versioned, authenticated and integrity-checked. Colour contrast was computed from the actual theme values and passes WCAG AA everywhere that was measured (body text 11.2:1, muted text 4.7:1, buttons 6.7:1, calendar chips 10+:1) — status is never colour-only and the dialogs are native `<dialog>` elements, so keyboard and screen-reader basics are sound.

Three things were found that I would call real defects rather than polish, none of them an emergency: permanently deleting an organisation or project that has financial records linked to it fails with a misleading error (a foreign-key constraint the delete path forgot to clear, verified by experiment); a shared HEIC/HEIF photo whose sending app omits the MIME type is accepted by the share-target and then refused at upload (the manifest, the share helper and the two upload paths disagree about which extensions are allowed); and `image/svg+xml` uploads are accepted and served inline, which is an unnecessary door for a hostile file even between two trusted users. Beyond those, the most user-visible improvement available is not a feature at all: the document viewer and upload dialog still speak in developer/sandbox language ("Arena preview", container paths, `df -h` instructions) to the two people this app is for, and a calm sweep of that copy is cheap and worthwhile.

**Top 3 recommendations:** (1) one small bug-fix PR covering the permanent-delete foreign-key gap, the HEIC extension list and the SVG hardening, each with a regression test; (2) a calm-copy sweep that moves troubleshooting language out of the UI and into the README; (3) basic continuous-integration checks on pull requests, because today nothing runs automatically between "agent says it's green" and "tag publishes an image". Everything else in this document is ranked below those and can wait for your choice.

## 4. Not recommended (considered and deliberately left out)

- **Multi-user roles, private-to-one-user data, multi-estate support.** Hard guardrail of the product; the two-equal-users model is load-bearing in the schema, the auth config (which refuses anything but exactly two users) and the tone. Reconsidering any of this would be a new product, not a change to this one.
- **Legal, tax, debt-priority or entitlement calculations; deadline auto-calculation.** Guardrail, enforced today by tests that assert no figures appear. The app's value is that it organises what the users were told, not that it guesses.
- **Offline caching of records or documents; push/email notifications.** Deliberate privacy and calm decisions, restated in every release. Nothing found in this review argues for reopening them.
- **Scan UI, vendor partnerships, auto-categorisation, merging photos into PDF.** Settled in the multi-page-scan decision (Route 2 only — the app receives what the phone shares). The HEIC fix in N1 stays strictly within "accept what was shared".
- **A visual redesign or restyling screens piecemeal.** You have approved the current layout and theme; the theme-ready token architecture exists so that any future restyle happens at the registry level, not screen by screen. Contrast measured in this review passes AA throughout, so there is no accessibility case for change either.
- **Replacing `window.confirm`/`prompt` with custom modal dialogs.** Native dialogs are accessible, focus-safe and honest; a bespoke system would be work with no user-visible gain. Revisit only if a calm-design reason appears (e.g. the DELETE-typed prompt feeling abrupt — wording can be tuned without new machinery).
- **Pagination or virtualisation of the task/event/finance lists, and a move to a heavier database.** Premature at two users and one estate; the snapshot model is a deliberate simplicity win. The targeted fixes in F14/F15 cover the real costs.
- **Bypassing `/share-target` in Cloudflare Access.** Explicitly rejected in v0.2.13 and correctly so: the 303 must carry the Access session for the subsequent `GET /` to be authenticated.
- **Making `latest` immutable or pinning Unraid to version tags.** Worth considering one day, but with manual Force Update as the only update path and the documented failed-tag recovery procedure, the current arrangement is safe enough; changing it adds ceremony for two users.
